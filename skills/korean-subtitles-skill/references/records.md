# CLI packets for assigned authors and reviewers

Use `python3 scripts/subtitles.py COMMAND`. The fresh contract is `english-ssot-output-v7`; the project also pins the mechanical engine hash. A changed engine requires fresh preparation, with no approval migration. E/K are selected originals, O is surviving English-anchored output, and S is a supplement. IDs/timing do not establish semantic correspondence. [Collection and initial study](collection.md) must already be complete before correction; assigned workers do not repeat preparation or research. Generated packets fill bindings and hashes; submit only Korean and necessary judgments.


## Claim the next eligible episode

An assigned job worker starts with `handoff REQUEST_ROOT --worker ACTUAL_SESSION_ID`. Use the actual session identity consistently, never a new alias to evade its two-episode context limit. Even an item locator resolves to its complete canonical request, so it cannot reset the session's job count. The command uses the canonical current phases, keeps unfinished owned work first, then picks an eligible independent review before a new correction. It never assigns the first corrector to their own review or takes another assigned review. Initial collection and the applicable prior study remain required. The returned `assignment` gives the actual item/role and session item count; its first normal author/reviewer packet already includes factual study and a generated `response_template` under that item's `responses` directory. Read the packet and only the guidance/evidence applicable to that role. No coordinator-authored interpretation or second source preread is needed.

Continue the assigned episode with ordinary `view --pending`, packet submissions and explicit author seal or independent approval. Submit that explicit terminal record with `submit ITEM RECORD --next`. This validates the requested seal/approval and returns `next` from canonical dispatch in the same transaction. It never invents a language decision or automatically approves/finalizes. On failure neither phase change nor next claim commits. The returned next source packet is already issued to this worker: use it directly, without another `handoff` or initial `view`.

When `next` contains an assignment, send one concise completed-item/phase/next-assignment event to the coordinator, then continue that next episode without waiting for acknowledgement. Include no source body or author verdict. When no assignment remains, return the completed item/phase and `next.action`/`next.ready` in the final report; do not send a duplicate completion message or make a separate end-state handoff. A coordinator wakes an eligible waiting session only after an actual readiness event. Separate `handoff` remains available for initial assignment and that actual wake-up. `wait` ends active work until a real eligibility/completion event; do not poll. Its `ready` list is phase/ownership metadata for dispatch, not another source presentation. `retire` prohibits a third distinct episode; `done` means all language jobs are approved, and the coordinator performs batch finalize. Stopped-reviewer handover still needs the existing explicit reason and fresh personal coverage; dispatch never borrows another reviewer's reading.

For an explicitly assigned item, the existing role-specific `view` still works. `--template` without a path generates a safe response filename automatically; edit the returned file. An explicit destination remains supported inside the actual item's `responses` directory. Do not reconstruct a path from the batch parent or regenerate hashes/bindings.
